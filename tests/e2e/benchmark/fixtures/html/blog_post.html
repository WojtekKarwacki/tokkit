Mastering Python Async/Await: Patterns and Pitfalls

Python's async/await syntax has matured significantly since its introduction in Python 3.5. In this guide, we'll explore practical patterns for writing efficient concurrent code and the common mistakes you should avoid.

Share: Twitter LinkedIn HN

Why Async Matters

When building I/O-bound applications — web scrapers, API clients, database-driven services — synchronous Python forces your program to wait for each operation before starting the next. Async Python lets you overlap these waits, dramatically improving throughput without the complexity of threads or multiprocessing.

The key insight: async code is single-threaded but concurrent. The event loop handles many pending tasks, switching between them whenever one is waiting on I/O.

Core Patterns

1. Concurrent Requests with gather()

The most common async pattern is firing multiple coroutines concurrently and waiting for all of them:

import asyncio
import aiohttp

async def fetch(session, url):
    async with session.get(url) as response:
        return await response.json()

async def fetch_all(urls):
    async with aiohttp.ClientSession() as session:
        tasks = [fetch(session, url) for url in urls]
        results = await asyncio.gather(*tasks)
    return results

# Fetches 10 URLs concurrently instead of sequentially
urls = [f"https://api.example.com/item/{i}" for i in range(10)]
results = asyncio.run(fetch_all(urls))

With synchronous requests, 10 calls at 100ms each would take ~1 second. With gather(), they complete in roughly 100ms — a 10x speedup.

2. Semaphore for Rate Limiting

Unconstrained concurrency can overwhelm a server or hit API rate limits. Use a semaphore:

async def fetch_with_limit(urls, max_concurrent=5):
    semaphore = asyncio.Semaphore(max_concurrent)

    async def bounded_fetch(session, url):
        async with semaphore:
            return await fetch(session, url)

    async with aiohttp.ClientSession() as session:
        tasks = [bounded_fetch(session, url) for url in urls]
        return await asyncio.gather(*tasks)

3. Error Handling

By default, gather() propagates the first exception and cancels remaining tasks. Use return_exceptions=True to collect all results and handle errors per-task:

results = await asyncio.gather(*tasks, return_exceptions=True)
errors = [r for r in results if isinstance(r, Exception)]
successes = [r for r in results if not isinstance(r, Exception)]

Common Pitfalls

The most common async mistake is calling a sync blocking function inside a coroutine. This blocks the entire event loop.

PyCon 2023, "Async Antipatterns" talk

Watch out for these pitfalls:

  1. Blocking the event loop: Never call time.sleep(), requests.get(), or any synchronous I/O inside a coroutine. Use asyncio.sleep() and aiohttp instead.
  2. Forgetting await: If you call a coroutine without await, it returns a coroutine object instead of executing. Python will warn you, but the bug can be subtle.
  3. Creating tasks too early: asyncio.create_task() schedules immediately. Don't create tasks in module scope before the event loop starts.
  4. Not cancelling tasks on shutdown: Leaked tasks consume resources and can cause warnings. Always cancel and await pending tasks on exit.

The asyncio.run() entry point

Since Python 3.7, asyncio.run() is the recommended way to start your async program. It creates a new event loop, runs your coroutine, and cleans up properly:

async def main():
    # Your async code here
    results = await fetch_all(urls)
    for result in results:
        process(result)

if __name__ == "__main__":
    asyncio.run(main())
